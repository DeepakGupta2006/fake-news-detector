# Fake News Detector

Paste a news article/headline → the model predicts **Real** or **Fake** with a
confidence score. TF-IDF + Logistic Regression, served through a Flask API,
with a simple HTML/CSS/JS frontend.

This whole project is included and **tested to run end-to-end** in this
folder, using a small **synthetic demo dataset** (see the note below —
important).

## About the datasets

There are two CSVs in `data/`:

- **`real_dataset.csv`** (the default, and what the trained model in
  `models/` was built from): **39,102 real news articles** from the
  **ISOT Fake News Dataset** (University of Victoria) — 21,196 real
  articles crawled from Reuters.com and 17,906 fake articles from sites
  flagged unreliable by Politifact, mostly 2016-2017, covering both U.S.
  politics and world news (broader than just the election). Pulled from
  a public GitHub mirror of the dataset.
- **`sample_data.csv`**: a tiny 300-row *synthetic* dataset (generated by
  `data/generate_sample_data.py`) with obviously exaggerated templates
  ("SHOCKING", "wake up sheeple"). It exists only to sanity-check that the
  pipeline runs end-to-end in seconds — its accuracy on itself isn't
  meaningful, just a smoke test.

### A leakage bug I found and fixed in this dataset

The raw ISOT data has a well-known issue: ~92% of the real (Reuters)
articles literally start with a dateline like `WASHINGTON (Reuters) -`.
Left in, a model doesn't need to learn anything about writing style — it
just learns "contains the word Reuters" = REAL, which is trivial and
wouldn't generalize to any other real news source. Before training, this
project strips that dateline and every other mention of "Reuters" from
the text (see the cleaning step in `data/real_dataset.csv`'s generation),
along with a few fake-article site-tag artifacts ("21st Century Wire",
"Featured image" boilerplate). Removing the leak barely moved accuracy at
all (98.4% either way) — a strong sign the model is actually learning
genuine style differences, not the shortcut.

### Honest results

Training on `real_dataset.csv` (TF-IDF + Logistic Regression, 10k features)
gets:

| Metric | Score |
|---|---|
| Accuracy | 98.4% |
| Precision | 98.4% |
| Recall | 98.4% |
| F1 | 98.4% |

Top weighted words confirm genuine, defensible signal: REAL is driven by
formal wire-service conventions (`said`, `told reporters`, `spokesman`,
`president donald`, weekday datelines like `wednesday`/`thursday`),
while FAKE is driven by informal blog-style cues (`video`, `watch`,
`via`, `breaking`, `just`, first-name-only references like `hillary`).

I also tested it on hand-written sentences **outside** the training
distribution (economy, sports, and a nonsense command-line string) to
check real generalization, not just held-out accuracy on the same corpus:

| Test input | Result |
|---|---|
| "The Federal Reserve raised interest rates... Fed Chair Jerome Powell told reporters..." | REAL, 94.8% confidence |
| "The Lakers defeated the Celtics 112-108... the team said in a statement." | REAL, 90.4% confidence |
| "You won't believe this SHOCKING video... share before it's deleted!" | FAKE, 98.4% confidence |
| "python -m http.server 8000 --bind 127.0.0.1 is real" (nonsense) | FAKE, 66.2% confidence (correctly uncertain — low signal either way) |

This is a meaningful improvement over the earlier, smaller, single-topic
dataset — it now generalizes reasonably well beyond just 2016 election
political news.

### Remaining limitations (worth knowing)

1. **Still time/era-biased**: articles are from 2016-2017. Very recent
   events, people, or terminology (post-2017) won't be well represented.
2. **Style, not truth, is what's being detected**: like any classifier of
   this kind, it recognizes *how* real vs. fake articles of this era were
   *written* — formal wire-service language vs. informal blog style — not
   whether a claim is factually true. A well-written false claim, or a
   sloppily-written true one, can fool it. This is worth a paragraph in
   any project report.
3. **Short text is still noisier than full articles/paragraphs** — see the
   command-line test above landing at just 66% confidence.

## Step 1 — Install dependencies

```bash
cd fake-news-detector
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Step 2 — (Optional) Get an even bigger/broader dataset

The repo already ships with `data/real_dataset.csv` (39,102 real ISOT
articles, cleaned) and a model in `models/` already trained on it — you
can skip straight to Step 4 if you just want to run it.

If you want more/newer data, look for a more recent fake-news dataset
(post-2017) and merge it in using the same two-column format:

```python
import pandas as pd
new_data = pd.read_csv("your_new_data.csv")  # must have text, label columns
existing = pd.read_csv("data/real_dataset.csv")
combined = pd.concat([existing, new_data]).drop_duplicates(subset=["text"])
combined.to_csv("data/real_dataset.csv", index=False)
```

## Step 3 — Train the model

```bash
python ml/train_model.py --data data/real_dataset.csv --max-features 10000
```

This prints accuracy/precision/recall/F1 and a confusion matrix, then saves:
- `models/model.joblib`
- `models/vectorizer.joblib`
- `models/metrics.json`

Re-run this any time you change the dataset or want to retrain.

### (Optional) Test a prediction from the terminal, no API needed

```bash
python ml/predict.py "Researchers at the university published a peer-reviewed study on vaccine efficacy."
```

## Step 4 — Start the API

```bash
python api/app.py
```

Runs on `http://localhost:5000`. Check it's alive:

```bash
curl http://localhost:5000/health
```

Test a prediction directly:

```bash
curl -X POST http://localhost:5000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "Scientists confirm new findings after months of peer review."}'
```

## Step 5 — Open the frontend

With the API still running in one terminal, in another terminal:

```bash
cd frontend
python3 -m http.server 8000
```

Then open **http://localhost:8000** in your browser. Paste an article,
click **Analyze**, and you'll see the Real/Fake label, a confidence bar,
and a running history of your last 5 checks.

(You can also just double-click `frontend/index.html` to open it directly
in a browser — it'll still work as long as the Flask API is running,
because `flask-cors` is enabled on the backend.)

If your API runs somewhere other than `localhost:5000`, change `API_URL`
at the top of `frontend/script.js`.

## How it works (pipeline)

1. **Preprocess** (`ml/preprocess.py`): lowercase, strip URLs/HTML/punctuation,
   remove stopwords (using a small built-in list — no NLTK download needed).
2. **Vectorize**: `TfidfVectorizer` turns cleaned text into numeric features
   (unigrams + bigrams, top 5000 features by default).
3. **Classify**: `LogisticRegression` predicts REAL vs FAKE and a probability
   for each class.
4. **Serve**: Flask loads the saved model + vectorizer **once at startup**
   and exposes `/predict`.
5. **Display**: the frontend calls `/predict`, shows a color-coded result
   card, a probability bar, and keeps a short history in memory.

## Realistic accuracy expectations

| Approach                        | Typical accuracy |
|----------------------------------|-------------------|
| TF-IDF + Logistic Regression (this project, on `real_dataset.csv`, leakage removed) | **98.4%** (measured) |
| LSTM / GRU                        | ~94-96% (general benchmark) |
| Fine-tuned BERT / DistilBERT      | ~97-99% (general benchmark) |

Note this project's number is *higher* than the general LSTM benchmark
range — that's because the ISOT dataset's fake vs. real articles have
quite distinct writing styles (formal wire service vs. informal blog), not
because this beats BERT in general. See the limitations section above.

Important caveat for any project report: these numbers are benchmark
numbers on curated datasets. Real-world fake-news detection is harder -
style-based classifiers can be fooled by well-written misinformation, and
"true/false" isn't always binary. This is worth a section in your write-up.

## Ideas to extend this project

- **Explainability**: highlight the words that most influenced the
  prediction (e.g. with LIME or SHAP).
- **Source credibility check**: cross-reference the source domain against
  a list of known unreliable sites.
- **URL input**: scrape article text automatically from a pasted URL
  (e.g. with `newspaper3k` or `BeautifulSoup`).
- **Database + login**: store past checks per-user (Postgres/MongoDB) and
  show a real history, not just an in-memory one.
- **Admin dashboard**: total checks, real/fake ratio, most-flagged domains.
- **Upgrade the model**: swap TF-IDF+LogReg for embeddings (Word2Vec/GloVe)
  or a fine-tuned DistilBERT for higher accuracy (needs more compute).
- **Browser extension**: flag likely-fake content directly on any webpage.

## Troubleshooting

- **"Could not reach the API"** in the frontend → make sure `python api/app.py`
  is running and `API_URL` in `script.js` matches its address.
- **"Model not loaded"** error from `/predict` → run
  `python ml/train_model.py` first, then restart `api/app.py`.
- **CORS errors in the browser console** → confirm `flask-cors` installed
  correctly (`pip install flask-cors`) - it's what allows the frontend page
  to call the API from a different origin/port.
